# LangChain RAG Debugging

A beginner-friendly **end-to-end RAG implementation using LangChain**, focused on understanding and debugging each stage of the pipeline.

## 🔄 RAG Flow

```text
Document
   ↓
Text Splitting
   ↓
Embeddings
   ↓
Chroma Vector DB
   ↓
Retriever
   ↓
Relevant Context
   ↓
Prompt
   ↓
LLM
   ↓
Answer
```

## 🛠️ Tech Stack

* Python
* LangChain
* Hugging Face Embeddings
* Sentence Transformers
* ChromaDB
* OpenRouter
* LangSmith

## 🔐 LangSmith Setup

LangSmith is used to **trace and debug the RAG pipeline**.

### 1. Create a LangSmith account

Go to **LangSmith** and create an account.

### 2. Create an API key

After logging in:

```text
LangSmith Dashboard
      ↓
Settings
      ↓
API Keys
      ↓
Create API Key
```

Copy the generated API key.

### 3. Create a LangSmith project

In the LangSmith dashboard, create a project named:

```text
langchain-rag-debugging
```

This project will contain the traces generated by this application.

### 4. Configure `.env`

Create a `.env` file in the project root:

```env
OPENROUTER_API_KEY=your_openrouter_api_key

LANGSMITH_API_KEY=your_langsmith_api_key
LANGSMITH_TRACING=true
LANGSMITH_PROJECT=langchain-rag-debugging
```

### 5. Run the application

```bash
python main.py
```

Ask a question through the application.

### 6. View the trace

Open the `langchain-rag-debugging` project in LangSmith.

You can inspect the complete flow:

```text
User Question
      ↓
   Retriever
      ↓
Retrieved Chunks
      ↓
Context + Prompt
      ↓
     LLM
      ↓
   Answer
```

##  LangSmith Debugging

LangSmith helps identify where a RAG application is going wrong.

You can inspect:

* ❌ Wrong documents retrieved
* ❌ Poor chunking
* ❌ Missing context
* ❌ Incorrect prompt
* ❌ Unexpected LLM response
* ⏱️ Slow components

The main question is:

> **Why did my RAG application give this answer?**
